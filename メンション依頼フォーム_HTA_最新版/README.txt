メンション依頼フォーム HTA v28.22
============================================================

■ ベース
リポジトリ main の v28.21（5c8e77c）から更新。

■ v28.22の変更
・3件すべての「必須」表示ラベルを削除。
・「オプション」見出しを常時表示。未選択時はチェック項目のみ非表示。
・入力欄、ラジオボタン、チェックボックスの見出しと縦位置を統一。
・横の基本間隔を12pxとし、右側の入力欄と操作ボタンの列を整列。
・追加調整：代理CA名とオプションの間隔を12pxから32pxへ拡大。
・入力欄の幅を保つため、フォーム本体の幅を1480pxから1500pxへ拡大。
・フッターの拠点欄と送信ボタンも、カード内の入力欄の左右に整列。
・送信前確認ポップアップに、表示中の依頼ごとの「CA名・出社状況・メールメモ」を表示。
・同一CA設定中も、依頼1／2／3それぞれを個別の行として表示。

■ 同梱内容（一式）
・メンション依頼フォーム.hta：フォーム本体
・mention-form.js：入力チェック・表示制御・送信受付
・mention-form.css：表示・配置
・mention-request-worker.js：バックグラウンドでCSVへ書き込む送信処理
・README.txt：この説明書
・書き込み用フォルダ：CSV保存先（案内テキスト入り）

■ 更新方法
フォームを閉じ、ZIPを展開して、使用中のフォームと同じフォルダへ上書きしてください。
既存の「書き込み用」フォルダ内のCSVは残して、そのまま使用してください。
v28.22を適用済みで間隔調整だけを反映する場合は、mention-form.cssの上書きで反映できます。

■ 出社状況（必須・初期値は未選択）
・出社：代理CA名をクリアして非活性化。「至急」のみ表示。
・公休／時短（時間外）：代理CA名を1名以上必須。「代理CA記載なし」のみ表示。
・代理CA記載なし：代理CA名をクリアして非活性化。空欄で送信できます。
・オプション見出しは、未選択・クリア・同一CA解除後も表示します。
・出社状況が未選択の間は、オプションのチェック項目のみ非表示。
・状態変更で非表示となるチェックは解除し、送信値に残しません。

■ 同一CA
・組織、CA名、出社状況、代理CA名3欄、オプションを直前の依頼から引き継ぎます。
・引き継ぎ中は上記項目を編集不可とし、元の変更を依頼1→2→3の順に反映。
・チェック解除で引き継いだ項目をクリア。メールメモ以降は各依頼で入力します。
・入力時の注意事項は同一CAチェック中のみ非表示。
・依頼2の取消で繰り上げる際は、依頼3の値を保持し、元の連動関係を整理します。

■ 送信前確認
・入力チェック後に「出社状況は相違ないですか？」を表示。
・「はい」で送信処理を開始。「いいえ」またはEscで入力を保持してフォームへ戻ります。
・確認中のTab移動は「はい」「いいえ」の間に限定。

■ CSV出力（最新版）
フォームの現行項目に合わせ、CSVを次の16列へ更新します。
送信日時 / RequestID / 拠点 / 依頼者 / 依頼番号 / 組織 / CA名 / 出社状況 / 代理CA1 / 代理CA2 / 代理CA3 / オプション / メールメモ / 処理日時 / 期日または面接日程 / タイプ

・出社状況：画面で選択した「出社」「公休」「時短（時間外）」をそのまま出力。
・オプション：該当時に「至急」または「代理CA記載なし」を文字で出力。該当なしは空欄。
・代理CA組織、旧「時短」専用列、旧「至急」専用列は廃止。
・旧17列PendingはWorkerで引き続き再送可能。
・同じ日・同じ拠点に旧17列CSVが既に存在する場合は、列混在を防ぐため最新版を「_v28.22.csv」へ分離して保存します。

■ 検証範囲
簡易DOMモデルを使って、既存テストのロジック部分と必須ラベルの削除を確認（56項目）。
未入力時のアラート、状態切替、同一CA連鎖、取消・クリア、送信前確認を含みます。
CSSの配置寸法も確認。ブラウザ描画・Windows HTAでの実表示・共有CSVへの実送信は未実施です。
入力チェック・送信UIは維持し、CSV生成とWorkerのCSVスキーマ処理のみ最新版へ更新しています。

■ CSV最新版対応 Fix
・画面の現在項目に合わせてCSV出力を16列へ更新。
・出社状況とオプションを文字列で出力。
・Workerの書き込み／再読込検証も16列へ対応。
・旧17列Pendingの再送互換を維持。

■ 送信失敗ポップアップ Fix
・Pending保存後、Worker側で共有CSVへの送信処理を完了できなかった場合、Windows標準のエラーポップアップを最前面表示します。
・ポップアップはOKを押すまで表示し、「未送信を再送」から再送するよう案内します。
・新規送信直後の失敗では受付モーダルとの重なりを避け、受付OK／フォーム終了の合図を待って表示します（最大30秒）。
・起動時の自動再送や手動再送など、既存Pendingの失敗は待機せず通知します。
・Pendingは削除せず保持するため、従来どおり再送可能です。
